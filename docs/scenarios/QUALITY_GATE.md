# Πύλη ποιότητας ανά σενάριο (ιδιοκτήτης 17/10)

> «Δεν έχει νόημα να "περνάει" το Σενάριο 01 μόνο επειδή χτίστηκε χωρίς exception και μετά να μεταφέρουμε κρυφά
> προβλήματα στα επόμενα 9.»

## Κανόνας ροής

S01 → πλήρης λίστα → βρίσκουμε πρόβλημα → διορθώνεται → **ξανατρέχει ΟΛΗ η λίστα S01** → μόνο όταν είναι καθαρό πάμε
στο S02. Μετά S02 → όλη η λίστα → διορθώσεις → επανάληψη S02 → S03 … → S10.

Αν μια διόρθωση στο Sxx μπορεί να επηρεάσει προηγούμενα σενάρια → **regression S01…S(xx−1)** πριν συνεχίσουμε.

## Τι κρατάμε στο Git για κάθε σενάριο

- `docs/scenarios/Sxx_<όνομα>.archforge`: το πραγματικό αρχείο που ανοίγει ο ιδιοκτήτης στο ArchForge.
- `docs/scenarios/Sxx_REPORT.md`: κάθε έλεγχος **PASS / FAIL / FIXED**, τι βρέθηκε, ποιο αρχείο άλλαξε, σε ποιο
  commit.
- Στιγμιότυπα (2D, 3D, Structural, βασικές όψεις Η/Μ) δίπλα τους. **Τα κοιτάμε πραγματικά** — δεν αρκεί το pytest.

## Η λίστα

### 1. Σχεδιαστικό / αρχιτεκτονικό
- όροφοι και διαφορετικά υψόμετρα
- τοίχοι / χώροι / επιφάνειες
- δάπεδα και οροφές
- σκάλες + **πραγματικές οπές πλακών**
- μπαλκόνια / κιγκλιδώματα
- κεραμοσκεπές / σοφίτες
- κουζίνα / μπάνιο / έπιπλα
- 2D και 3D οπτικός έλεγχος
- save → close → reopen χωρίς απώλειες

### 2. Στατικό
- κολώνες, δοκοί, πλάκες / επίπεδα
- συνέχεια μεταξύ ορόφων
- θεμελίωση όπου υποστηρίζεται
- structural analysis χωρίς crash
- κάθε warning/failure εξετάζεται, δεν αγνοείται
- **κανένας κανόνας `ENGINEER_REVIEW` / UNVERIFIED δεν βαφτίζεται «verified»**

### 3. Μηχανολογικά
- ύδρευση κρύο/ζεστό· επιλογή διαφορετικού συστήματος σωληνώσεων
- αποχέτευση
- ηλεκτρολογικά
- θέρμανση/HVAC όπου υπάρχει
- σύνδεση πηγή → δίκτυο → τελικό σημείο (γράφος συνδεσιμότητας — ο ιδιοκτήτης: «δεν συνδέονται όλα παντού»)
- συνέχεια μεταξύ ορόφων
- τεχνική κάτοψη κατανοητή από τρίτο άνθρωπο
- BOM / ποσότητες

### 4. Προσφορά
- ποσότητες από το **ίδιο authoritative model**
- κοινό price book
- υλικά χωριστά, εργασία χωριστά
- σύνολα ανά ειδικότητα + συνολικό έργο
- missing/partial τιμές **φαίνονται** και δεν συμπληρώνονται αυθαίρετα
- καμία ψεύτικη «τιμή αγοράς»

### 5. Συμπεριφορά προγράμματος
- select / move / edit · undo / redo · delete
- αλλαγή ορόφου · αλλαγή συστήματος · save/load
- καμία εξαφάνιση στοιχείων άλλου ορόφου
- καμία αλλοίωση άλλου trade από αλλαγή ενός trade

### 6. Οπτικός έλεγχος
- screenshot 2D, 3D, Structural, βασικών MEP views — και τα κοιτάμε.

## Κανόνες περιεχομένου σεναρίων (ιδιοκτήτης 17/10)
- Κάθε σενάριο **πολύπλοκο**, με **διαφορετικά στοιχεία** από τα άλλα (ανεβαίνει η δυσκολία).
- Μέσα σε κάθε σενάριο: **Η/Μ, κουζίνες, μπάνια, έπιπλα**.
- Το σύνολο κάθε σεναρίου βγαίνει σε **προσφορά**.

## Παράδειγμα γιατί χρειάζεται
Το σενάριο 02 βρήκε ότι η «Οροφή σοφίτας» έμπαινε και σε χαμηλότερους ορόφους (10 οροφές αντί για 4). Ένα απλό
«scenario built successfully» δεν θα το είχε πιάσει.
